## 三、分层与模块架构规范
### 核心分层职责
| 层级        | 职责说明                         | 开发约束与注意事项                                               |
|-------------|----------------------------------|----------------------------------------------------------------|
| **Controller** | 处理 HTTP 请求与响应，定义 API 接口 | 不得直接访问数据库，必须通过 Service 层调用；禁止直接调用AI能力 |
| **Service**    | 实现业务逻辑、事务管理与数据校验   | 必须通过 Repository 层访问数据库；返回 DTO 而非 Entity（除非必要） |
| **Repository** | 数据库访问与持久化操作             | 继承 `JpaRepository`；使用 `@EntityGraph` 避免 N+1 查询问题     |
| **Entity**     | 映射数据库表结构                   | 不得直接返回给前端（需转换为 DTO）；包名统一为 `entity`         |

### 项目专属模块职责
| 模块名 | 职责说明 | 开发约束 |
|--------|----------|----------|
| agent | 智能体核心逻辑，负责对话调度、流程控制、意图识别 | 不得直接操作数据库，需通过Service层调用；核心逻辑需做单元测试覆盖 |
| rag | 检索增强生成模块，负责面试题向量化、相似度检索、上下文召回 | 向量化逻辑需统一封装，禁止硬编码向量模型参数；检索结果需做去重、排序处理 |
| mcp | 模型上下文协议模块，负责对接外部大模型能力、Prompt管理 | Prompt内容统一存放在resources目录下，禁止硬编码；大模型调用需做异常处理、降级逻辑 |
| skill | 面试技能模块，封装各类面试场景的评分、反馈、题目生成逻辑 | 技能逻辑需可扩展，新增面试场景无需修改核心agent逻辑 |
| memory | 记忆模块，负责对话历史、用户画像、面试记录的存储与管理 | 历史数据存储需做冷热分离，避免内存占用过高；敏感数据需加密存储 |
| auth | 认证授权模块，负责用户登录、权限校验、Token管理 | 遵循OWASP安全规范，禁止Token泄露、越权访问 |
| config | 配置类模块，统一管理项目配置、第三方组件配置 | 敏感配置（如大模型API密钥、数据库密码）需加密存放，禁止硬编码 |
| converter | 转换器模块，负责不同对象之间的转换（如Entity与DTO、VO的转换） | 转换逻辑统一封装，禁止在Controller层手动拼接对象 |
| handler | 处理器模块，负责全局异常处理、参数校验增强、跨域处理等 | 统一异常处理逻辑，禁止在业务层直接抛出未处理异常 |
| loader | 加载器模块，负责面试题、Prompt模板、配置文件的加载 | 加载逻辑需做缓存，避免频繁IO操作 |

### 接口与实现分离
- 所有接口实现类需放在接口所在包下的 `impl` 子包中。

## 四、安全与性能规范
### 输入校验
- 使用 `@Valid` 与 JSR-303 校验注解（如 `@NotBlank`, `@Size` 等），注意Spring Boot 3.x中校验注解位于 `jakarta.validation.constraints.*`
- 禁止手动拼接 SQL 字符串，防止 SQL 注入攻击
- 用户输入需做敏感词过滤，禁止传入违规内容
- 禁止向大模型传入用户敏感信息（如手机号、身份证号等）

### 事务管理
- `@Transactional` 注解仅用于 **Service 层**方法
- 避免在循环中频繁提交事务，影响性能

### AI专项安全规范
- AI生成的内容需做合规校验后再返回给前端，禁止直接输出未经验证的内容
- 大模型API密钥、向量数据库密码等敏感配置需加密存放，禁止提交到代码仓库
- 禁止利用项目能力生成违规、违法内容

### 性能规范
- RAG检索时需控制返回的面试题数量，默认不超过10条，避免返回过多内容影响响应速度
- 对话历史存储需做冷热分离，超过7天的历史数据自动归档到冷存储
- 接口响应时间超过1s的需做异步处理或逻辑优化，避免阻塞主线程
- 面试题加载、Prompt模板加载需做本地缓存，避免频繁IO操作

## 五、代码风格规范
### 命名规范
| 类型       | 命名方式             | 示例                  |
|------------|----------------------|-----------------------|
| 类名       | UpperCamelCase       | `UserServiceImpl`     |
| 方法/变量  | lowerCamelCase       | `saveUser()`          |
| 常量       | UPPER_SNAKE_CASE     | `MAX_LOGIN_ATTEMPTS`  |

### 注释规范
- 所有类、方法、字段需添加 **Javadoc** 注释，**统一使用中文**，专有名词、API标识符可保留英文
- 复杂业务逻辑需添加行内注释，说明实现思路
- 禁止使用无意义的注释（如“getter方法”“setter方法”等）

### 类型命名规范（阿里巴巴风格）
| 后缀 | 用途说明                     | 示例         |
|------|------------------------------|--------------|
| DTO  | 数据传输对象                 | `UserDTO`    |
| DO   | 数据库实体对象               | `UserDO`     |
| BO   | 业务逻辑封装对象             | `UserBO`     |
| VO   | 视图展示对象                 | `UserVO`     |
| Query| 查询参数封装对象             | `UserQuery`  |

### 实体类简化工具
- 使用 Lombok 注解替代手动编写 getter/setter/构造方法：
  - `@Data`
  - `@NoArgsConstructor`
  - `@AllArgsConstructor`

### 包结构规范
- 后端包统一按模块划分，每个模块对应独立的功能包（如agent、rag、mcp等）
- 同模块下的接口与实现分离，实现类统一放在`impl`子包中
- 工具类统一放在`util`包下，禁止在业务模块中编写通用工具逻辑

## 六、扩展性与日志规范
### 接口优先原则
- 所有业务逻辑通过接口定义，具体实现放在`impl`包中，便于后续扩展与mock测试

### 日志规范
- 使用 `@Slf4j` 注解代替 `System.out.println`
- 关键业务节点（如AI调用、RAG检索、用户登录、面试评分等）需打印日志，包含请求参数、响应结果、耗时等信息
- 禁止打印敏感信息（如用户手机号、身份证号、API密钥、AI生成的敏感内容等）到日志中
- 日志级别规范：普通业务日志用INFO，异常日志用ERROR，调试日志用DEBUG，生产环境默认关闭DEBUG级别

## 七、编码原则总结
| 原则       | 说明                                       |
|------------|--------------------------------------------|
| **SOLID**  | 高内聚、低耦合，增强可维护性与可扩展性     |
| **DRY**    | 避免重复代码，提高复用性，AI相关逻辑（如Prompt、向量化逻辑）需统一封装 |
| **KISS**   | 保持代码简洁易懂，AI调用逻辑需做封装，禁止在业务层直接调用大模型API |
| **YAGNI**  | 不实现当前不需要的功能，避免过度设计AI能力 |
| **OWASP**  | 防范常见安全漏洞，如SQL注入、XSS、敏感信息泄露等 |
| **AI合规** | AI生成内容需符合法律法规要求，禁止生成违规内容，所有AI能力调用需留痕 |

## 八、数据目录规范
- `data/questions`：面试题存储目录，按技术栈分类存放（分布式、Go、MQ、MySQL、Redis等），新增面试题需按对应分类目录存放，文件格式统一为Markdown
- `data/eval/reports`：面试评估报告存储目录，评估结果统一按`日期_用户ID_面试ID.md`的格式命名存放，禁止随意修改历史报告内容
